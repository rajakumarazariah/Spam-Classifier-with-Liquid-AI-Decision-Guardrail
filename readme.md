# AI Spam Message Detector with Decision-Model Guardrails

A production-grade, two-tier spam detection system designed for SMS and short messaging platforms. The service pairs a fast local TF-IDF + Calibrated Logistic Regression model with a secondary, zero-token **Liquid AI Decision Model (`d1.1`)** guardrail to adjudicate ambiguous and adversarial edge cases. Failure analysis and post-mortems are conducted via **Groq LLM endpoints**.

---

## Architecture Overview

```
                        Incoming SMS Text
                                │
                                ▼
               ┌─────────────────────────────────┐
               │   Stage 0: Text Preprocessing   │
               │   - NFKC normalization          │
               │   - Tokenizes URLs, phones, cur │
               │   - Normalizes leetspeak        │
               └────────────────┬────────────────┘
                                │
                                ▼
               ┌─────────────────────────────────┐
               │    Stage 1: Primary Classifier  │
               │    Word + Char TF-IDF + Cal. LR │
               │    Outputs P(spam) ∈ [0.0, 1.0] │
               └────────────────┬────────────────┘
                                │
                 Is model confidence ambiguous?
                 (0.35 ≤ P(spam) ≤ 0.70)
                              /   \
                            YES    NO
                            /       \
                           ▼         ▼
┌─────────────────────────────────┐  ┌───────────────────────────────────┐
│ Stage 2: Liquid AI Decision     │  │ Deterministic Local Output:       │
│ Guardrail (d1.1 System One)     │  │ P(spam) < 0.35  -> HAM            │
│ Structured zero-token 'noul'   │  │ P(spam) > 0.70  -> SPAM           │
└────────────────┬────────────────┘  └───────────────────────────────────┘
                 │
                 ▼
       Final Prediction Output

```

### Why This Design?

1. **Low Latency & High Throughput:** Over 90% of routine traffic (obvious spam and unambiguous ham) is evaluated in less than 5 milliseconds locally via linear subword/word n-gram models.
2. **Adversarial Resilience:** Spammers use character substitutions (homoglyphs, leetspeak) and urgency misdirection. Character n-grams (3–5 subword windows) capture structural obfuscation without dictionary blowout.
3. **Guardrail Calibration:** Borderline instances (such as urgent legitimate notifications, delivery alerts, or short sign-offs like *"Waiting for your call"*) activate the Liquid AI decision model to eliminate false positives without manual rule drift.

## Step-by-Step Execution

### Step 1: Train the Base Classifier

The training script reads `spam.csv`, performs a stratified 80/20 train/test split, fits a hybrid Word + Subword Char TF-IDF feature extractor, trains a balanced Logistic Regression model, and saves the pipeline:

```bash
python train.py

```

*Output: Saves pipeline weights to `model/tfidf_lr_pipeline.joblib`.*

---

### Step 2: Evaluate Model Metrics

Runs inference on the unseen 20% test partition to measure discrimination quality:

```bash
python evaluate.py

```

**Expected Performance:**

* **Accuracy:** ~98.5%
* **Spam Precision:** ~98%
* **Spam Recall:** ~93% – 95%
* **F1-Score (Spam):** ~0.95
* **ROC-AUC:** > 0.985

---

### Step 3: Run Hard-Example Failure Analysis

Identifies test set classification misses (False Positives and False Negatives) and queries Groq to explain why the statistical n-gram representation failed:

```bash
python hard_examples.py

```

*Example analysis output:*

> **Message:** `"Waiting for your call."`
> **Ground Truth:** HAM | **Model Confidence P(Spam):** 0.7007
> **Groq Analysis:** High concentration of isolated tokens (`call`, `waiting`) heavily associated with premium callback scams in the training corpus, paired with minimal conversational context, driving an artificial probability surge.

---

### Step 4: Run the FastAPI Prediction Service

Start the ASGI server via Uvicorn:

```bash
uvicorn main:app --reload --port 8000

```

## Key Design Decisions & Justifications

1. **Subword Character N-Grams:** Classical word tokenizers fail completely on `c@sh`, `w1nner`, and zero-width spaces. Evaluating subword character 3-to-5-grams captures leetspeak patterns without requiring manual dictionary substitution for every variant.
2. **Why a Calibrated Linear Model?** Linear classifiers maintain ultra-low latency (~2 ms per message on single-core CPU) and prevent catastrophic drift. Output calibration ensures confidence scores map directly to expected posterior probabilities.
3. **Liquid AI Structured Primitive (`noul`):** Traditional LLMs are prone to hallucinated formatting and latency spikes. Liquid AI's `noul` primitive returns a mathematical likelihood score directly, matching backend SLA requirements.
